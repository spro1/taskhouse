팀의 업무를
우리 서버 안에서

Taskhouse는 소규모 조직과 팀이 자기 서버에 설치해 쓰는 이슈 트래커입니다. 백로그, 스프린트, 보드를 한곳에 두고, 업무 데이터를 회사 밖으로 내보내지 않습니다.

이런 팀을 위해 만들었습니다

이슈 트래커 하나 쓰려 해도 계약, 사용자 수, 외부 저장 승인이 걸렸다면.

5~100명 규모의 조직

라이선스 비용도, 갱신 때마다 사용자 수를 세는 일도 없습니다.

밖으로 나가면 안 되는 업무

보안 정책, 고객 요구, 폐쇄망 때문에 SaaS를 쓸 수 없어도 됩니다. 모든 것이 우리 서버에 있습니다.

전담 운영 인력이 없는 팀

서버 한 대에 컨테이너 셋. 설치, 업그레이드, 백업이 각각 스크립트 하나입니다.

즐겨 쓰는 트래커에 필요한 것

Jira에 익숙한 사람이면 바로 쓸 수 있게 만들었습니다.

📋

이슈

에픽, 스토리, 작업, 버그, 하위 작업(계층 검사), 서식 있는 설명과 댓글, @멘션, 연결, 첨부, 지켜보기, 전체 변경 이력. 두 사람이 다른 필드를 고치면 서로 덮어쓰지 않습니다.

🏃

스크럼

끌어서 순서를 바꾸는 백로그, 완료하면 남은 이슈를 옮기는 스프린트, 카드를 끌면 상태가 바뀌는 보드. 검색, 담당자, 내 이슈만 빠른 필터.

🔀

워크플로

기본은 자유 이동. 상태와 전이마다 누가 쓸 수 있는지, 조건(열린 차단 이슈 없음, 하위 작업 완료, 필수 필드), 이동 후 처리를 정합니다.

👆

빠른 사용

이슈는 오른쪽 패널에 열리고, 어디서나 C로 이슈를 만들고, ⌘K로 키 이동과 검색. 다른 사람의 변경이 바로 보입니다.

🔎

검색

JQL 부분집합인 TQL(CHANGED, linked, membersOf() 등)과 필터 칩이 같은 엔진. 저장된 필터. 한국어 조사 처리. 볼 수 없는 이슈는 나오지 않습니다.

🔒

권한

사람이나 그룹에 주는 프로젝트 역할 4종과 공개 범위 3종. 권한 밖 이슈는 모든 경로에서 404입니다.

🔔

알림

앱 내 알림, 메일 묶음, 서명하고 재시도하는 웹훅, Slack, Mattermost, Teams. 볼 권한이 있는 사람에게만 갑니다.

🤖

AI 에이전트

내장 MCP 서버: 개인 API 토큰으로 이슈 검색, 생성, 수정, 상태 이동, 댓글. 권한은 토큰 주인과 같습니다.

🔑

로그인

초대 링크로 만드는 계정, 또는 관리 화면에서 켜는 OpenID Connect SSO(Keycloak으로 확인). 팀 위키 Pagehouse와 계정을 공유할 수 있습니다.

데이터는 우리 서버를 떠나지 않습니다

외부 폰트, CDN, 사용 통계가 없습니다. 밖으로 나가는 요청은 직접 켠 기능뿐입니다.

데이터 위치PostgreSQL과 파일 볼륨, 모두 우리 서버. 밖으로 나가는 요청은 설정한 SSO, 메일, 웹훅뿐입니다.
인터넷 없이컨테이너 이미지가 든 오프라인 번들로 설치하고 업그레이드합니다.
잃어버리지 않음매일 자동 백업, 업그레이드와 복원 전에도 한 번씩. 이슈의 모든 변경은 이력에 남습니다.
보안로그인 시도 제한, 감사 로그, 암호화된 SSO·웹훅 비밀값, 엄격한 Content-Security-Policy, 루프백·링크 로컬 주소로 가지 않는 웹훅.
떠날 때프로젝트 전체를 JSON(설명, 댓글, 연결, 이력 포함)으로, 이슈 목록을 CSV로 내보냅니다.

서버 한 대, 명령 한 줄

Docker 24+ 또는 Podman 4+가 있는 Linux 서버(amd64, arm64).

릴리스 번들 인터넷 없이

릴리스 페이지에서 번들과 SHA256SUMS를 받습니다. 번들에 이미지가 들어 있어 아무것도 내려받지 않습니다.

sha256sum -c SHA256SUMS --ignore-missing
tar xzf taskhouse-<version>-amd64.tar.gz && cd taskhouse-<version>
scripts/install.sh images.tar

소스에서

서버에서 이미지를 빌드하고, DB 비밀번호와 암호화 키를 만들고, 서비스를 시작합니다.

git clone https://github.com/spro1/taskhouse.git && cd taskhouse
scripts/install.sh

Pagehouse 옆에

이 서버에서 Pagehouse를 이미 쓰고 있다면, Taskhouse가 그 데이터베이스와 계정을 함께 씁니다.

scripts/install.sh --share-with /opt/pagehouse images.tar

설치가 끝나면 첫 계정용 setup token이 출력되고, 그 계정이 관리자가 됩니다. 설치 안내와 업그레이드 안내를 보세요.

자주 묻는 질문

정말 무료인가요?

네. Apache-2.0 라이선스의 오픈소스이고 사용자 수 제한도 없습니다. 서버 비용만 듭니다.

인터넷이 필요한가요?

아니요. 릴리스 번들로 설치하면 설치, 사용, 업그레이드 모두 인터넷 없이 됩니다.

회사 계정(SSO)으로 로그인할 수 있나요?

네. OpenID Connect를 관리 → 사람과 SSO에서 켭니다. Keycloak으로 확인했고, IdP 그룹과 관리자도 반영됩니다.

위키와 함께 쓸 수 있나요?

네. Pagehouse(팀 위키)는 별도 제품이지만 같은 데이터베이스에 설치하면 Taskhouse와 계정을 공유합니다. 한 번 로그인하면 둘 다 열리고 서로 링크됩니다. 사람, 그룹, SSO 설정은 한 벌이고, 역할과 권한은 제품마다 따로입니다. 설치 안내를 보세요.

Jira에서 옮겨올 수 있나요?

아직 Jira 가져오기 기능은 없습니다. REST API나 MCP로 이슈를 만들 수 있습니다.

문제를 찾았거나 제안이 있나요?

GitHub 이슈로 알려 주세요. 보안 문제는 SECURITY.md에 적힌 대로 비공개로 알려 주세요.
