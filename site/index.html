What a tracker people like to use needs

Made so that anyone used to Jira feels at home.

📋

Issues

Epics, stories, tasks, bugs and sub-tasks with the hierarchy checked, rich-text descriptions and comments with @ mentions, links, attachments, watching and full history. Two people editing different fields never overwrite each other.

🏃

Scrum

A backlog you rank by dragging, sprints that carry unfinished issues over, and a board where dragging a card changes its status. Quick filters by text, assignee and "only mine".

🔀

Workflows

Free movement by default. Statuses and transitions with who may use them, conditions (no open blockers, sub-tasks done, required fields) and what happens afterwards.

👆

Fast to use

Issues open in a side panel, C creates an issue anywhere, ⌘K jumps to a key or searches. Changes by others appear live.

🔎

Search

TQL, a JQL subset with CHANGED, linked and membersOf(), and filter chips on the same engine. Saved filters. What you can't see never appears.

🔒

Permissions

Four project roles for people or groups and three visibility levels. Issues outside your permissions answer 404 on every path.

🔔

Notifications

In the app, email digests, signed webhooks with retries, and Slack, Mattermost or Teams. Only ever to people who may see the issue.

🤖

AI agents

A built-in MCP server: agents search, create, update, move and comment on issues with a personal API token and exactly your permissions.

🔑

Sign-in

Accounts from invite links, or OpenID Connect SSO turned on from the admin screen (tested with Keycloak). Accounts can be shared with Pagehouse, the team wiki.

Your data never leaves your server

No external fonts, CDNs or telemetry. The only outbound requests are features you turn on.

Where data livesPostgreSQL and a file volume, all on your server. Outbound requests only for the SSO, email and webhooks you configure.
No internetInstall and upgrade from an offline bundle that carries the container images.
Nothing lostAutomatic daily backups, plus one before every upgrade and restore. Every change to an issue stays in its history.
SecuritySign-in throttling, an audit log, encrypted SSO and webhook secrets, a strict Content-Security-Policy, and webhooks that never reach loopback or link-local addresses.
LeavingExport a whole project as JSON (descriptions, comments, links and history) and issue lists as CSV.

One server, one command

A Linux server (amd64 or arm64) with Docker 24+ or Podman 4+.

Release bundle Works offline

Download the bundle and SHA256SUMS from the releases page. The bundle carries the images, so nothing is downloaded.

sha256sum -c SHA256SUMS --ignore-missing
tar xzf taskhouse-<version>-amd64.tar.gz && cd taskhouse-<version>
scripts/install.sh images.tar

From source

Builds the images on the server, writes the database password and encryption key, and starts the service.

git clone https://github.com/spro1/taskhouse.git && cd taskhouse
scripts/install.sh

Next to Pagehouse

Already running Pagehouse on this server? Taskhouse joins its database and its accounts.

scripts/install.sh --share-with /opt/pagehouse images.tar

The installer prints a one-time setup token for the first account, which becomes the administrator. See the install guide and the upgrade guide.

Questions

Is it really free?

Yes. It's open source under Apache-2.0 with no user limits. You only pay for the server.

Does it need internet access?

No. Installing from the release bundle, using and upgrading all work without it.

Can people sign in with company accounts (SSO)?

Yes, with OpenID Connect, turned on in Admin → People & SSO. It has been tested with Keycloak, and provider groups and admins come along.

Does it work with a wiki?

Yes. Pagehouse (team wiki) is a separate product, but installed into the same database it shares Taskhouse's accounts. One sign-in opens both and each links to the other. People, groups and SSO settings exist once; roles and permissions stay per product. See the install guide.

Can we move from Jira?

There is no Jira importer yet. Issues can be created over the REST API or MCP.

Found a problem or have an idea?

Open a GitHub issue. Report security issues privately, as described in SECURITY.md.
